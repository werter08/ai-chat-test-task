# CLAUDE.md — rules for the agent

Project: **AIChat**, a ChatGPT-style iOS 18+ chat app (plus a macOS target). Task: `docs/TASK.md` · Plan: `docs/PLAN.md` · Design: `docs/ARCHITECTURE.md` · Verification: `docs/TESTING.md`.

## Stack
- Swift 5 mode, SwiftUI, SwiftData (persistence), Observation (`@Observable`), `URLSession` + SSE for streaming.
- Project generated by **XcodeGen** from `project.yml`. Never hand-edit or commit the `.xcodeproj`.
- Dependencies: Swift Package Manager only. Currently none — keep it that way unless justified (a third-party drawer library was evaluated and rejected: tiny, stale, no interactive drag).
- Deployment targets: iOS 18.0, macOS 15.0. iOS 18 APIs (`ScrollPosition`, `onScrollGeometryChange`) are fine; anything newer needs `if #available`.
- AI backend: OpenRouter (`/api/v1/chat/completions`, `stream: true`). Model id comes from `.env`; default `baidu/ernie-5.5-flash-preview:free` — the **`:free` suffix is required** (the bare id returns 404).

## Layout
- `Shared/` — all app code, compiled into both the iOS and macOS targets. `#if os(...)` only when unavoidable.
  `App/` entry + debug fixtures · `Models/` · `Networking/` · `Security/` · `Features/` views, `ChatEngine`, Markdown, reveal logic.
- `Config/` xcconfig (optional gitignored `Local.xcconfig` for signing/bundle id) · `Mac/` entitlements · `Tests/` unit · `UITests/` XCUITest · `scripts/` helpers · `docs/`.

## Rules
1. **Secrets and privacy:** never print, log, commit or paste the API key. `.env`, `Config/Local.xcconfig`, `scripts/redact.local.txt`, `ai-logs/` and `Design/` are gitignored. Only the obfuscated `Secrets.generated.swift` carries a key, and the *committed* version is the empty placeholder (`git update-index --skip-worktree` protects the local one). Use `<API_KEY>` in docs. Do not put personal identifiers in committed files.
2. Keep layers separate: views → `ChatEngine` (state + orchestration) → `ChatStreaming` protocol (`OpenRouterClient`) → network. Views never touch URLSession.
3. Every network failure maps to a `ChatAPIError` with a user-facing message; the UI must offer **Retry** for it. **Stop is not an error**: keep the partial reply and add a `note` message.
4. Streaming must be cancellable; the assistant message is created lazily on the first token; deleting a chat mid-generation must not touch it.
5. Scrolling: reopened chats start at the newest message; when the user sends, scroll their message to the top and do **not** follow the reply; show **Go down** when the reply is ready and below the fold.
6. UI must work in light and dark, on iPhone and Mac. Controls with transparent backgrounds need `contentShape` so the whole area is tappable. Backgrounds that should reach the screen edge must ignore the safe area.
7. **Verify, don't assume.** A visual change is not done until a UI test or screenshot confirms it; tests must assert the thing (e.g. dark mode samples brightness) rather than merely pass. Report failures honestly, with output.
8. Commit in small steps with clear messages. Never commit `.env`, `build/`, `*.xcodeproj`, logs or design assets.

## Commands
- Build + run on simulator: double-click `Build.command` (or `bash Build.command`). It reads the bundle id from the built app, so a local override is fine.
- Tests: `xcodegen generate && xcodebuild test -project AIChat.xcodeproj -scheme AIChat -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO` (add `TEST_RUNNER_SHOT_DIR=<dir>` for UI-test screenshots, `TEST_RUNNER_RUN_LIVE_TESTS=1` for the live API tests).
- Debug launch flags (Debug builds only): `-uiTestInMemory`, `-uiTestSeedMarkdown`, `-uiTestFakeStream`.
- AI logs for submission: `bash scripts/export_ai_logs.sh` (removes images, keys, personal data; re-run at the very end).
- If `xcodebuild` hangs even for `-list`, a stale `SWBBuildService` is the usual cause — stop it and retry.
